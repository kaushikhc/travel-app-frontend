## Where things stand
- Scaffold with feature folders: auth, profile, trip, memories, capture, explore, navigation.
- Profile sends the device IANA time zone (`flutter_timezone`) whenever it differs from the server's; countries come from `GET /api/places/countries` (`CountryPicker`, searchable).
- Profile photo: picking a photo uploads it straight away through the media API (`MediaRepository.uploadPhoto`: `POST /api/media/uploads`, PUT the bytes to the signed URL with a plain Dio, `POST /api/media/{id}/complete`), and saving sends `photoMediaId` (needs backend kaushikhc/travel-app#37). The profile's `photoUrl` is the signed link to show. Never send base64 in `photoUrl`; the backend rejects it.
- Birthday: `BirthdayPicker` (day, month, year dropdowns; no impossible or future dates), sent as `yyyy-MM-dd` (`ApiDate`). There is no Age input: the server works out `age` from the birthday. Birthday is only returned by `GET /profile/me`, so other travelers never see it.

They pick a username and an optional password, or skip to keep the Google email. `AuthNotifier.chooseUsername` swaps in the new token the server returns (needs backend kaushikhc/travel-app#39).

- Home header (PR #40): the avatar opens the Profile tab (`AppRoutes.profile`); the bell opens `NotificationsView` (`lib/features/notifications`, route `/notifications` = `AppRoutes.notifications`, inside the shell). Has Edit and Delete icon buttons (see Edit trip).
- Create trip (`CreateTripView`, route `/trips/new`, registered before `/trips/:id`; "New trip" button on Home): `TripRepository.createTrip` posts `POST /api/trips` with name (required), description, optional start/end dates (`yyyy-MM-dd`), optional cover (picked and uploaded at once, sends `coverMediaId`) and comma-separated tags. Mirrors the backend rules: name required; end date needs a start date and cannot be before it; tags trimmed, case-insensitive dedupe, max 30, 100 chars each. No dates = DRAFT; status is server-derived and never sent. Server `{message}` errors show in a snackbar. On success Home and stats providers are invalidated and the screen pops. Long-press a date button to clear it.

Saving invalidates trip detail, Home and stats, then pops. Delete (`DELETE /api/trips/{id}`, confirm dialog) on trip detail returns to Home.

## Auth design (PR "Auth rework")
- `AuthNotifier` (`features/auth/presentation/auth_state.dart`) owns the session: states checking, unauthenticated, loading, authenticated, error. At start it restores the token from `TokenStorage` (`core/storage`, flutter_secure_storage) and checks it with `/auth/check`: rejected tokens are dropped, an unreachable server keeps the session.
- `ProfileNotifier` rebuilds on sign-in and sign-out and loads `/profile/me` itself.
- The router's redirect is `authRedirect` (`core/router/auth_redirect.dart`), a pure function of auth state, profile state and URL. It never changes state, which is what broke routing before.
- Web Google callback: `/#/?code=...` renders `GoogleCallbackView`, which exchanges the code; a race with session restore is handled (the newer sign-in wins).
- Android Google: `NativeGoogleSignInGateway` (google_sign_in 7) needs `--dart-define=GOOGLE_SERVER_CLIENT_ID=<web client id>`, plus an Android OAuth client in Google Cloud for the package name and signing SHA-1.

## How to run
- Backend CORS allows only the `Authorization`, `Content-Type` and `Accept` headers. Don't add other default headers for non-ngrok hosts, or browser calls fail as "could not reach the server".
- Photo uploads in dev go to the local S3 server from the backend's `docker compose up -d` (localhost:9090). A phone cannot reach that address, so the app fails with "Upload failed at storage: Connection refused". On the backend (develop), set `APP_STORAGE_RELAY_BASE_URL` to the one ngrok address of the backend and the backend relays the bytes (no second tunnel). See the backend's PROJECT_STATUS.md, "Testing photos from a phone". For the deployed web build, the R2 bucket needs a CORS rule for the app's origin.
- Photo upload errors: `MediaRepository.uploadPhoto` throws `MediaUploadException` naming the step (`start`, `storage`, `confirm`) and the HTTP status; the snackbars show it (`photoUploadError`). Picker failures show "Could not open the photo picker"; other unexpected errors show their type.
- Photo rotation: phone JPEGs often rely on an EXIF orientation flag. `uprightPhoto` (`features/media/data/photo_orientation.dart`, runs in an isolate) bakes the rotation into the pixels and drops the flag before every upload; upright JPEGs and non-JPEGs pass through untouched. Both `FilePicker.pickFiles` image calls pass `compressionQuality: 0`: file_picker's Android default re-encodes at quality 30, which strips the flag but leaves the pixels sideways (and cuts quality), so rotation can no longer be fixed afterwards. HEIC is not straightened.
- PC, Chrome: `flutter run -d chrome --web-port 8080 --dart-define-from-file=env/dev.json` (port 8080 is where the backend sends Google sign-in back; on localhost the app calls `http://localhost/api`).
- Android emulator: `--dart-define=API_BASE_URL=http://10.0.2.2/api` (or an env file; 10.0.2.2 is the PC). Debug builds allow plain http for this; release builds need https.

```
flutter pub get
flutter run --dart-define-from-file=env/dev.json --dart-define=GOOGLE_SERVER_CLIENT_ID=<web client id>
flutter analyze && flutter test
```
